# FatCodex

[English](README.md) · **Русский**

Дневник питания в одном поле ввода. Пишешь, диктуешь или фотографируешь еду, приложение само разбирает, что съедено, считает КБЖУ и ведёт дневник. Никаких форм и поиска продуктов вручную.

Личный проект без монетизации (название: FatSecret + Codex). Сервер не обязателен: приложение целиком работает на телефоне, см. [Локальный режим](#локальный-режим). Свой сервер нужен, если хочется лучшего разбора и распознавания речи.

## Как это работает

```
Android (Compose, Room)  ──JWT──▶  gateway  ──▶  ai-parser ──▶ DeepSeek
   offline-first, очередь            │     └──▶  nutrition  (USDA + Open Food Facts, SQLite)
   WorkManager                       └────────▶  stt        (faster-whisper small, CPU)
                              Postgres (пользователи, дневник)    Redis (кэш разбора)
```

- Модель **только называет продукты и граммы**. Калории она не выдумывает: цифры берёт сервис `nutrition` из локальной базы. Если продукт не нашёлся, запись остаётся без цифр, а приложение задаёт один вопрос.
- Уверенность ниже 0,6 даёт один короткий уточняющий вопрос. Ответом на него служит следующее сообщение.
- «Масла было меньше», «это была половина», «убери хлеб» обновляют существующие записи, а не создают новые.
- Всё хранится локально в Room, а сервер догоняет: сообщение без сети ждёт в очереди и отправится само. Повторная отправка безопасна (идемпотентность по `client_id`).
- Ключ DeepSeek лежит только в контейнере `ai-parser`. Приложение его не видит.
- Цель по калориям ниже 1 200 ккал не принимается (и клиентом, и сервером), формулировки нейтральные.

## Что можно написать

| Ввод | Что произойдёт |
|---|---|
| `овсянка 60 г, банан` | две записи с КБЖУ |
| `вес 82.4` | запись веса (тренд: скользящее среднее за 7 дней, график в итоге дня) |
| `масла было меньше` | правка уже записанного масла |
| `как обычно` | подставится привычный приём пищи (после трёх повторов) |
| фото тарелки | разбор по картинке |
| микрофон | распознавание на устройстве, а если недоступно, запись уходит на `stt` (только с сервером) |

Нажатие на строку открывает правку на месте, нажатие на итог дня показывает детали.

## Локальный режим

На экране входа выбери «без сервера»: почта не нужна, дневник хранится на телефоне. Затем один раз вставь **свой ключ DeepSeek** (его можно пропустить, тогда работает только встроенный словарь) и задай цель.

- Ключа в APK нет: ты вводишь его сам, он лежит в приватных настройках приложения. Модель получает только то, что ты написал или сфотографировал, запрос идёт напрямую на `api.deepseek.com` и больше никуда. Для этого нужен интернет, без связи текст разбирается словарём.
- Каталог **USDA SR Legacy** (около 7 800 строк, 170 КБ) лежит в APK. Поиск портирован с сервера на Kotlin.
- **Словарь на русском** (около 200 продуктов и блюд: борщ, пельмени, гречка) переводит слова в запрос к каталогу и знает вес штуки, ложки, стакана, порции. Блюда без аналога в USDA считаются по таблице и помечаются знаком «~»: это оценка, а не точная цифра.
- Сложные фразы и **фото** разбирает DeepSeek, который работает как агент над базой продуктов. Он ищет по твоей базе, таблице блюд, USDA и в интернете (DuckDuckGo) и **предлагает** значения. Без твоего выбора в базу ничего не попадает.
- Своя база продуктов лежит на телефоне рядом с дневником. Её можно править в приложении, вести из чата, экспортировать в `dietapp-foods.json` и импортировать обратно.
- Голос только через распознавание на телефоне. Для русского может понадобиться скачать офлайн-пакет в настройках Android.
- Дневник и выбранный режим входят в автобэкап Android. Токен и ключ DeepSeek не входят.
- Если модель недоступна, текст разбирается словарём, а в ленте есть пометка. Настройки → **Журнал** показывает каждое обращение к DeepSeek и причину, по которой приложение перешло на словарь.

Подробное описание локального режима, агента и базы продуктов: [docs/details.ru.md](docs/details.ru.md).

## Запуск бэкенда

Нужен только для серверного режима. Нужны Docker и ключ [DeepSeek](https://platform.deepseek.com/).

```bash
cp .env.example .env            # впиши POSTGRES_PASSWORD, JWT_SECRET, DEEPSEEK_API_KEY
docker compose up -d --build    # первый запуск сам скачает базу USDA (~7 МБ) и модель Whisper (~470 МБ)
docker compose logs gateway | grep "LOGIN CODE"   # код входа, пока не настроен SMTP
```

`JWT_SECRET` можно сгенерировать так: `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Gateway откажется стартовать со значением `change-me`. Код входа приходит на почту, если в `.env` заполнен `SMTP_*`, иначе он печатается в лог gateway.

## Установка приложения

Нужны JDK 17+ и Android SDK. Проще всего открыть папку `android/` в Android Studio.

```bash
cd android
./gradlew assembleRelease                                         # только на телефоне, без сервера
./gradlew assembleRelease -PapiBaseUrl=http://192.168.1.50:8080   # со своим сервером
adb install -r app/build/outputs/apk/release/app-release.apk
```

- Эмулятор: `./gradlew assembleDebug`, адрес по умолчанию `http://10.0.2.2:8080` (это хост-машина).
- Телефон в той же Wi-Fi сети: в `.env` поставь `GATEWAY_BIND=0.0.0.0` и укажи в `-PapiBaseUrl` IP компьютера. Приложение ходит по обычному HTTP, поэтому делай так только в сети, которой доверяешь. Для интернета поставь перед gateway HTTPS (Caddy, nginx) и укажи `https://…`: cleartext в такой сборке выключен.
- Release-APK подписан отладочным ключом, для себя этого достаточно. Свой ключ: `android/keystore.properties` с полями `storeFile`, `storePassword`, `keyAlias`, `keyPassword` (файл в `.gitignore`).
- Размер release-APK около 2,7 МБ вместе с каталогом продуктов.

## Структура репозитория

```
android/            Gradle-проект (app, core-ui, data), version catalog в gradle/libs.versions.toml
services/gateway/   REST для приложения, вход по коду из письма, JWT, синхронизация
services/ai-parser/ вызовы DeepSeek, function calling, кэш в Redis, ретраи
services/nutrition/ поиск продуктов и расчёт КБЖУ (SQLite + FTS5), импорт USDA и Open Food Facts
services/stt/       faster-whisper
contracts/          OpenAPI каждого сервиса; тесты падают, если код разошёлся с файлом
docs/               подробное описание (по-русски) и иконка приложения
```

Больше данных о продуктах (архив USDA или дамп Open Food Facts) загружается командами `python -m nutrition.cli import-usda` и `import-off`, см. [docs/details.ru.md](docs/details.ru.md). Open Food Facts распространяется по лицензии ODbL, USDA FoodData Central находится в общественном достоянии.

## Ограничения

- Точность зависит от того, как модель назвала продукт. Поиск ранжирует названия USDA с учётом их устройства («Apples, raw», а не «Croissants, apple»), но это эвристика: проверь цифры, если что-то выглядит странно. Непонятное приложение не подставляет, а переспрашивает.
- Цифры, которые модель добавила в базу сама, это типичные значения для такого продукта, а не твоя этикетка. Они помечены «~», и их стоит поправить в «Базе продуктов», если есть упаковка.
- Агент не проверялся на настоящем DeepSeek: ходы с инструментами проверены на заглушке с ответами в формате OpenAI-совместимого API. Если DeepSeek ответит иначе (например, без вызова функции), приложение разберёт сообщение словарём и напишет об этом.
- Не проверено на реальном устройстве: все тесты идут на JVM (Robolectric). Docker-образы, настоящий DeepSeek и Postgres проверялись отдельными процессами и заглушками, но не целиком в `docker compose`.
- Схема БД на сервере создаётся при старте (`create_all`), миграций нет.
- Токен и ключ DeepSeek хранятся в обычных SharedPreferences приложения (не в Keystore). Токен даёт вход только на твой собственный сервер, а ключ можно отозвать на стороне DeepSeek.
- Без сервера нет синхронизации между телефонами: дневник живёт на одном устройстве (плюс автобэкап Android).
- Словарь локального режима небольшой и русский. Английские названия находятся прямо в каталоге USDA, остальное нужно моделью (ключ) или сервером.
